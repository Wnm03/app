## 3. Alasan perubahan

Sama pola persis dengan Tahap 7 — satu pintu baca generik menggantikan
`D.products.find(p => p.name.toLowerCase() === X.toLowerCase())` inline yang
terduplikasi di 6 tempat:

```js
const p = (typeof ProductStore !== 'undefined')
  ? ProductStore.findByName(name)
  : D.products.find((x) => x.name.toLowerCase() === String(name).toLowerCase());
```

— 0 rumus baru, 0 perubahan hasil pada kondisi normal (`ProductStore`
dimuat), 100% identik dengan perilaku lama kalau belum dimuat.

### Catatan teknis — 2 bug di test harness (bukan di kode aplikasi) yang ditemukan & diperbaiki sebelum test dianggap valid
Saat pertama ditulis, 4 dari 9 test baru gagal — diinvestigasi dan
terkonfirmasi **bug di test itu sendiri**, bukan di kode aplikasi:
1. **Assignment ke binding `let` yang di-expose `loadSource()` tidak
   ter-refleksi ke closure di dalam sandbox vm** (`ctx._shopPdfImportRows =
   rows` menimpa property di objek context, tapi variabel `let` di dalam
   script vm tetap menunjuk array lama). Diperbaiki dengan **memutasi array
   yang sama** (`ctx._shopPdfImportRows.push(...rows)`), pola yang sama
   persis sudah dipakai `tests/shop-pdf-import.test.js`.
2. **`assert.deepEqual` membandingkan 2 objek hasil dari 2 context `vm`
   terpisah** (realm berbeda -> `Object.prototype` berbeda referensi) gagal
   dengan pesan "Values have same structure but are not reference-equal"
   walau isinya identik. Diperbaiki dengan bandingkan lewat JSON
   round-trip (`JSON.parse(JSON.stringify(x))`) supaya yang dibandingkan
   murni nilai, bukan identitas objek lintas-realm.

Kedua fix ini murni di file test (`tests/.../wiring.test.js`), 0 perubahan
di kode aplikasi.
