## BUG-011 — `goToList()` index tombol tab salah (offset)

**File:** `modules/finance/filter-laporan.js`, fungsi `goToList()`
(fungsi `jump()` di dalamnya).

**Bug:** Index tombol `.cn-tab` untuk parameter `shopTabName` (Shop)
& `cnTabName` (Carnotes) dihitung lewat ternary hardcode yang tidak
cocok dengan urutan tombol aktual di DOM (`index.html`):

- `#page-shop .cn-tab`: urutan aktual
  `kasir=0,jual=1,etalase=2,produsen=3,riwayat=4,pelanggan=5,laporan=6,bi=7`.
  Kode lama: `tabs[shopTabName==='etalase'?1:shopTabName==='produsen'
  ?2:shopTabName==='riwayat'?3:shopTabName==='pelanggan'?4:0]` — semua
  index yang dicek offset **-1** dari index aktual.
- `#page-carnotes .cn-tab`: urutan aktual
  `insight=0,bbm=1,servis=2,pajak=3`. Kode lama:
  `tabs[cnTabName==='servis'?1:0]` — `'servis'` seharusnya index `2`,
  bukan `1`.

`setShopTab(t,el)`/`setCnTab(t,el)` memakai `t` (string, benar) untuk
toggle konten, tapi `el` (elemen dari index yang salah) untuk
`el.classList.add('active')` — jadi tombol yang ter-highlight beda
dari tab konten yang sebenarnya ditampilkan. Konten tetap benar,
murni indikator tab aktif yang salah.

Sebagai pembanding: parameter `keuTabName` di fungsi yang sama sudah
benar — pakai `KEU_TAB_ORDER.indexOf(keuTabName)` (dinamis).

**Repro manual (langkah 1 workflow):**
1. Buka halaman Kendaraan (page-carnotes).
2. Panggil `goToList('servisReminderCard','carnotes',4,null,'servis')`
   (caller nyata: `modules/vehicle/sparepart-servis.js:1180`; caller
   kedua: `_sparepartCards()` di `modules/finance/finance-dashboard.js`).
3. Konten Servis terbuka — **benar**.
4. Tombol tab yang ter-highlight `active`: **⛽ BBM** — **salah**
   (seharusnya 🔧 Servis). Dikonfirmasi lewat eksekusi nyata fungsi
   (fake DOM sesuai urutan `.cn-tab` di `index.html`), bukan cuma
   pembacaan kode.

**Fix:** Ganti hardcode ternary dengan pola `indexOf()` yang sudah
benar dipakai `keuTabName` di fungsi yang sama — tambah 2 konstanta
baru di scope module `filter-laporan.js`:

```js
const SHOP_TAB_ORDER=['kasir','jual','etalase','produsen','riwayat','pelanggan','laporan','bi'];
const CN_TAB_ORDER=['insight','bbm','servis','pajak'];
```

lalu `tabs[SHOP_TAB_ORDER.indexOf(shopTabName)]`/
`tabs[CN_TAB_ORDER.indexOf(cnTabName)]` (fallback index `0` kalau
`indexOf()` return `-1`, sama seperti pola `keuTabName`). 0 perubahan
lain — `setShopTab()`/`setCnTab()` sendiri, urutan tombol di
`index.html`, dan seluruh caller **tidak disentuh**.

**Regression test:** `tests/s335-bug011-gotolist-tab-active-index.test.js`
(3 test) — menjalankan `goToList()` ASLI (via `loadSource`) dengan fake
`document` yang meniru urutan `.cn-tab` aktual di `index.html`;
`setShopTab()`/`setCnTab()` ASLI juga dijalankan (diambil terisolasi
lewat brace-extraction supaya dispatcher render per-tab yang
dipanggilnya bisa di-stub noop, di luar cakupan bug ini). Assert:
tombol yang dapat class `active` == tab yang diminta.
- `cnTabName='servis'` → harus highlight `'servis'`, bukan `'bbm'`.
- `shopTabName='pelanggan'` → harus highlight `'pelanggan'`, bukan
  `'produsen'` (offset -1 lama).
- `shopTabName='etalase'` → harus highlight `'etalase'`, bukan
  `'jual'`.
