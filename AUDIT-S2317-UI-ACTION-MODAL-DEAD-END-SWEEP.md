# S2317 — UI Action / Modal Dead-end Sweep

## Status
**OPEN / EVIDENCE GAP — no production change**

## Scope
Static sweep for:
- `data-action` dispatch paths
- modal open/close action references
- Dashboard Hub action resolution
- obvious missing action names
- modal-only feature navigation
- module-load failure visibility

## Verified evidence

### 1. Delegated `data-action` architecture exists
The application uses `data-action` + `data-args` extensively in current HTML.
Examples found include:
- `setPeriode`
- `setShopPeriode`
- `openQS`
- `setCnTab`
- `openSimModal`
- `goToList`
- `finishOnboard`

This is consistent with the project's delegated action architecture.

### 2. Dashboard Hub has an explicit action resolver
`dashboard-hub.js` / `dashboard-hub(1).js` contain `_dashHubCallAction()`.
It resolves dotted names such as `WorthIt.open`, preserves the namespace
owner as `this`, and logs a warning when the resolved function is absent.

This reduces the risk of silent modal-only dead ends, but static presence does
not prove every registry entry resolves at runtime.

### 3. Modal entry points exist in HTML
Current HTML contains explicit modal actions such as `openSimModal`,
`openQS`, and the Car Notes tab actions. Onboarding also has a real
`finishOnboard` action.

### 4. Module-load failure is surfaced
`index.html` contains `window.__moduleLoadFail()` and attaches an `onerror`
handler to `app-bundle-a.min.js`. A visible failure banner is created if the
bundle fails to load.

## Important limitation

The available Library evidence does **not** provide a complete, current
runtime DOM/action inventory together with the loaded global function table.
Therefore the following cannot be truthfully marked PASS here:

- every `data-action` resolves to a callable function;
- every `data-args` shape matches its handler;
- every modal has a reachable close path;
- every Dashboard Hub registry action resolves;
- every dynamically-rendered action remains callable after re-render;
- touch/mobile interaction has no dead-end;
- no modal remains visually trapped above/below navigation.

A browser execution sweep is required for those claims.

## High-risk areas to verify next

1. All `data-action` values in `index.html` against actual global/namespaced
   functions after bundle load.
2. All Dashboard Hub `target.action` values.
3. Modal open → save/cancel/close → reopen.
4. Nested modal / quick-settings (`openQS`) flows.
5. Dynamic list buttons generated by `innerHTML`.
6. `data-args` special `$el` handling.
7. Missing module/bundle behavior.
8. Mobile back/close behavior.

## No defect declared

The static evidence found no single action that can safely be declared a
confirmed production dead-end from the retrieved material alone.

This is intentionally **not** a PASS: the missing runtime resolution matrix
is an evidence gap.
