# A-S2217 — Cross-tab restore convergence

## Finding
Restore already used CAS, but its successful commit did not announce the write to other contexts. Other tabs could keep displaying stale in-memory state until a later save exposed the CAS conflict.

## Repair
`_persistAtomicSnapshotWithAux()` now calls `_announcePersistenceWrite()` only after the CAS transaction succeeds and the writer token is advanced. CAS remains the correctness boundary; BroadcastChannel/storage notification is the convergence signal.

## Invariants
- Restore commit is still atomic with auxiliary stores and outbox.
- CAS conflict still aborts restore without stale rollback.
- Successful restore marks other contexts stale promptly.
- No duplicate event is generated by the notification itself.
