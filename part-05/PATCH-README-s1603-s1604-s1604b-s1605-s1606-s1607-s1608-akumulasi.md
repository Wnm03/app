tersisa **1 family** tanpa test file yang menyentuhnya langsung:
`modules/modals.js` — perhatikan ini file **top-level** di `modules/`,
BUKAN `modules/shared/modals.js`.

### Temuan

Investigasi menunjukkan `modules/modals.js` (top-level) sudah lama
didokumentasikan sebagai file **DEAD/ORPHAN** di
`AUDIT-S572-DUPLICATE-SOURCE-STALE-STATE.md` — salinan lama peninggalan
restrukturisasi folder Sesi 17-18, **tidak pernah direferensikan**
`scripts/build.js` (satu-satunya sumber modal HTML yang dibundel adalah
`modules/shared/modals.js`). Karena itu, menulis test **fungsional** untuk
isi file itu tidak ada gunanya — kodenya tidak pernah jalan di app
produksi.

### Fix sesi s1608 (0 perubahan source, 1 test baru)

yang disengaja" ini secara otomatis:

`tests/s1608-modules-modals-orphan-guard.test.js` (5 test):
1. `modules/modals.js` (orphan) masih ada di disk — kalau dihapus di masa
   depan (sesuai rekomendasi jangka panjang AUDIT-S572), test ini akan
   gagal dgn pesan jelas supaya sesi berikutnya ingat update/hapus test
   ini juga, bukan dibiarkan jadi referensi menggantung.
2. `modules/shared/modals.js` (LIVE) tetap ada.
3. `scripts/build.js` **TIDAK** mereferensikan literal path
   `modules/modals.js` sebagai sumber bundel — kalau suatu saat ada sesi
   lain (manusia/AI) tanpa sadar menghidupkan kembali file orphan ini ke
   daftar sumber build, test ini gagal sebagai sinyal dini SEBELUM
   ke-deploy dengan modal HTML yang salah/basi.

   sebagai satu-satunya sumber modal HTML.
5. Entry version-sync `MODAL_VERSION` di `build.js` tetap menunjuk ke
   `modules/shared/modals.js`, bukan orphan-nya.
