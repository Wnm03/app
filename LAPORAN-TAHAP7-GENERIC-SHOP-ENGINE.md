# LAPORAN — Tahap 7: Generic Shop Engine, Pricing & Inventory Integration

Baseline: `KW-fullrelease-v1047.zip`. Rilis hasil sesi ini: `KW-fullrelease-v1048.zip`
(build label `s376-generic-shop-engine-tahap7-pricing-inventory-integration`, `?v=1048`).

Prinsip yang dipegang: additive only, backward compatible, tidak mengubah
struktur `D.products`/IndexedDB/`save()`/format data/perilaku bisnis, tidak
mengubah algoritma `ProfitEngine`/`InventoryEngine`/`cobek-pricing.js`/
transaksi stok/import-export/`syncPairedPrice()`. `PricingService`/
`InventoryService` (SSOT bacaan, `modules/shop/generic/*.js`) dipakai lewat
guard `typeof` + fallback ke perilaku lama di setiap titik.

## 1. Audit

Diaudit ulang dari nol dari baseline v1047 (tanpa asumsi ada implementasi
Tahap 7 sebelumnya). `PricingService`/`InventoryService` sendiri (lapisan
generik, `getCost/getRetail/getReseller/getMargin`, `stockStatus`,
`valueAt/totalValue`) sudah ada di baseline dari sesi-sesi sebelumnya
(berlabel internal "Tahap 1–3" di komentar file — penomoran itu untuk sesi
Generic Shop Engine sebelumnya, berbeda dari "Tahap 7" pada instruksi sesi
ini; dicatat di sini murni sebagai informasi, tidak menghambat pekerjaan).
Yang BELUM ada: pemakaian accessor tsb di titik baca display/read-only
Pricing & Inventory yang jadi target sesi ini.

Semua lokasi baca `hargaBeli`/`hargaJual`/`hargaReseller`/`stock` di modul
Shop dipetakan & dikelompokkan:

### Aman di-wire (dieksekusi sesi ini)
| File | Fungsi | Field |
|---|---|---|
| `cobek-etalase.js` | `Etalase.renderList()` | stockCls/stockLbl → `InventoryService.stockStatus()`; harga jual/beli/reseller yang **ditampilkan** → `PricingService.getRetail()/getCost()/getReseller()` |
| `purchase-engine.js` | `PurchaseEngine.estimatedCost()` | `x.product.hargaBeli` → `PricingService.getCost()` |
| `cobek-order.js` | `Produsen.openHargaModal()` | label "harga jual" → `PricingService.getRetail()` |
| `cobek-order.js` | `Order.computeTotals()` | `p.hargaReseller`/`p.hargaJual`/`p.hargaBeli` → `getReseller()/getRetail()/getCost()` |
| `cobek-order.js` | `calculateSmartDelivery()` | `product.hargaBeli` (parameter `modal` ke `LogisticsEngine.plan()`) → `PricingService.getCost()` |

### Tidak diubah (dengan alasan — lihat §7)
- `Etalase.renderList()` rumus **margin/marginPct**
- `Order.computeTotals()` **rumus diskon** per-item (`hargaDefault - hargaDefault*diskonPersen/100`) & `finalHarga` (di `renderList`)
- `Order.populateProductSelect()` (`stok ${p.stock}`)
- `cobek-order.js` baris write `p.stock+=it.qty` (rollback stok saat hapus transaksi)
- `cobek-pricing.js`, `cobek-tx-cart.js`, `cobek-io.js` (algoritma rekomendasi harga/stok, transaksi kasir, format import-export)
- `business-intelligence-presenter.js` — sudah bersih, tidak ada raw read

Tidak ditemukan keputusan arsitektur yang ambigu; audit disampaikan ke user
sebelum coding (lihat riwayat percakapan), tidak ada blocker.

## 3. Alasan perubahan

Setiap titik baca murni **display/read-only** (bukan bagian dari rumus
bisnis: diskon, margin, restock cost aggregation, delivery/logistics
routing) dialihkan supaya field harga punya satu titik baca generik
(`PricingService`), konsisten dengan pola yang sudah dipakai di
`Etalase.totalModalStok()/totalNilaiJualStok()` & `InventoryEngine`
(Tahap 1-3 sebelumnya). Setiap perubahan memakai pola yang identik:

```js
const x = (typeof PricingService!=='undefined') ? PricingService.getX(p) : p.fieldAsli;
```

— 0 rumus baru, 0 perubahan hasil pada kondisi normal (PricingService
dimuat), dan 100% identik dengan perilaku lama kalau PricingService belum
dimuat (guard `typeof` + fallback).

## 8. Area yang SENGAJA tidak diubah

| Area | Alasan |
|---|---|
| `Etalase.renderList()` — rumus margin/marginPct | Basis rumus **beda** dgn `PricingService.margin()`/`ProfitEngine.margin()`: kartu produk pakai markup thd `hargaBeli` (`margin/hargaBeli*100`), sedangkan `PricingService`/`ProfitEngine` pakai basis revenue thd `hargaJual` (`profit/revenue*100`). Migrasi akan **mengubah angka yang tampil ke user** — di luar cakupan additive, dilaporkan sesuai instruksi, bukan diasumsikan aman. |
| `Order.computeTotals()` rumus diskon & `renderList()` `finalHarga` | Logic bisnis (potongan harga), bukan sekadar titik baca — dibiarkan utuh, hanya field mentah sumbernya yang dialihkan lewat accessor. |
| `Order.populateProductSelect()` (`stok ${p.stock}`) | Instruksi eksplisit user: dibiarkan. |
| `cobek-order.js` — `p.stock+=it.qty` (rollback saat hapus transaksi) | WRITE path (mutasi stok), bukan display read-only — di luar cakupan additive/read-SSOT sesi ini. |
| `cobek-pricing.js` (StockRekoWidget/PriceRekoWidget), `cobek-tx-cart.js`, `cobek-io.js` | Eksplisit di luar scope per instruksi user (algoritma rekomendasi, transaksi stok kasir, format import/export). |
